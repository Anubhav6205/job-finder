**Job Overview**

We are looking for a .NET Software Development Engineer in Test (SDET) to join our Engineering team. The team works across multiple Business Units and technology initiatives, supporting new product development, application enhancements, application modernization, and integrations.

The role requires strong C# coding skills applied to test automation across UI, API, and database layers. Our environment includes both modern applications and long-running legacy systems, so the SDET must be comfortable building automation for new features as well as adding regression coverage to legacy .NET applications that are being modernized.

The ideal candidate thinks like a developer and a tester, builds maintainable automation frameworks rather than one-off scripts, embeds quality into CI/CD pipelines, and uses AI-assisted tools to speed up test creation.

**Roles & Responsibilities**

* Design, build, and maintain test automation frameworks in C# / .NET for UI, API, and integration testing.

* Write automated functional, regression, smoke, and end-to-end tests.

* Automate REST API testing, including contract, negative, and data-driven tests.

* Validate data and business rules at the database layer using SQL.

* Integrate automated tests into CI/CD pipelines with quality gates and clear reporting.

* Build regression safety nets for legacy .NET applications before and during modernization.

* Review requirements and user stories for testability; define test strategy, test plans, and acceptance criteria with product and engineering.

* Perform exploratory and manual testing where automation is not cost-effective.

* Run basic performance and load tests, and help identify bottlenecks.

* Log, triage, and track defects; perform root cause analysis with developers.

* Manage test data and test environments.

* Track and report quality metrics (coverage, defect leakage, flaky test rate, pass rate).

* Participate in code reviews, including reviewing unit tests written by developers.

* Collaborate with engineers, product managers, and Business Unit stakeholders across multiple projects.
